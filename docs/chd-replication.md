# 追試: C-HD「ダイクストラより速い最短経路アルゴリズム」(vals.ai, 2026-09-20)

対象: [A Faster Shortest Path Algorithm](https://www.vals.ai/blogs/faster-shortest-path-algorithm) と
その成果物 [spicylemonade/c-hd-proof](https://github.com/spicylemonade/c-hd-proof)（スナップショット 2026-09-20）。
比較対象: このリポジトリの既存実装と、arXiv 2504.17033 (DMM+25) の BMSSP を論文どおりに実装し直したもの。
（文中のパスはリポジトリのルートからの相対パス）

## TL;DR

1. **C-HD の主張は漸近的なものに限られる。** O(m + n lg n) に勝つのは密度 √lg n ≲ m/n ≲ lg^{3/4} n の窓の中だけで、
   改善幅は lg^{1/12} n（n = 2^20 で 1.28 倍、ブログの例 n = 2^1000 でも 1.78 倍）。
   著者自身も「定数は天文学的」「実用的な高速化は主張しない」「大規模ベンチマークはしていない」と明記している。
2. **実行可能なコードは公開されていない。** Lean の `chdProgram` は `ℝ≥0` 上の深く埋め込まれた RAM 項で、
   `Program.run` は `noncomputable`。しかも n < 2^16 や窓の外では Bellman–Ford にフォールバックする。
   そこで論文 (paper/PAPER.md v2.0 と付属の B1 疑似コード PCv2.3) から **C-HD を Rust で独立実装**した（`src/chd.rs`）。
3. **正しさ**: C-HD と DMM+25 は Dijkstra と全頂点でビット単位に一致した（3000 個の小グラフ〔重み 0・同値・自己ループ・多重辺・到達不能を含む〕、中規模ランダム、グリッド、n = 2^14〜2^22 のベンチ全件）。
4. **速度**: C-HD は最速の Dijkstra（4-ary ヒープ）に対して、すべてのケースで遅かった。
   前処理込みで、ランダム疎グラフ（n = 2^14〜2^22）では **1.47〜7.3 倍**、グリッドでは **4.5〜7.3 倍**。
   前処理を除いたコア部分だけでも 1.12 倍以上遅い。
   二分ヒープの Dijkstra と比べると、n ≥ 2^20 の大きめの d でコア部分だけは 0.98〜1.13 倍と同程度になる。
5. **比較回数（計算量モデルそのもの）では C-HD は Dijkstra の 2.2〜4.0 倍**で、n = 2^22 までに逆転の兆しはない。
   コア部分の実時間の追い上げは lg^{1/12} n の効果ではなく、小さいヒープ・一括選択によるメモリ局所性の効果と見られる。
6. **DMM+25 (arXiv 2504.17033) を論文どおりに実装すると Dijkstra の 14〜121 倍遅い**（グリッドでは 38〜50 倍）。
7. **このリポジトリの既存の「高速化」主張は成り立たない。** `improved_sssp` は Dijkstra と同一コード、
   `improved_sssp_v2` の Bellman–Ford 相は到達不能、`core_algorithm` はトップ呼び出しで即座に
   `base_case`（= HashSet を使った完全 Dijkstra）に落ちる。README の 1.1〜1.6 倍は計測ノイズ
   （同一コードの V1 と `dijkstra` の比が、3 回の中央値を取っても 0.84〜1.12 倍に振れた。旧 README は 1 回計測）。

## 1. C-HD が主張していること

| 項目 | 内容 |
|---|---|
| 形式化された定理 | `chd_exact_within`: どの有向グラフ・非負実数重みでも厳密。コストは C·T_disp(n, m) 以下 |
| 上界 | m ≤ n·F(n)（F(n) = ⌊⌊log₂ n⌋^{3/4}⌋）のとき T_chd = n + m + m·ln(m/(n+1)+2) + m^{1/3}(n ln(n+2))^{2/3}。それ以外は (n+1)(m+1)（Bellman–Ford） |
| Dijkstra に勝つ範囲 | √lg n ≤ m/n ≤ F(n)。プロファイル m ≈ n lg^{3/4} n で O(n lg^{11/12} n) 対 O(n lg n) |
| 定数 | C = bodyC KcC + 65536·9 + 100 で「天文学的」。ワードは 161·log₂(n+m+2) ビット、空間は Θ(時間) |
| ディスパッチャ | log₂ n < 16 または ⌈m/n⌉ > F(n) なら Bellman–Ford |
| 実験 | 「小さな正しさシミュレーションのみ。大規模グラフでのベンチマークはしていない」 |

アルゴリズム本体は DMSY26 系 BMSSP（再帰的な境界付き多始点最短路）の改良で、主な変更点は次のとおり。

- **前処理**: 出次数チェーンで出次数を δ = max(3, ⌈2m/n⌉) 以下にする。各隣接リストは (w, head) でソートする。
- **FindPivots-HD**: 各 x ∈ S から k = ⌈√t⌉ 頂点までの局所探索を行う。新しく見つけた頂点を探索上限に数え、
  既存の木に触れたらマージする。d[v] ≺ L_X の辺は**恒久的に削除**する。
- **ポインタ走査**: ソート済みの静的 CSR の上をポインタで走査し、各辺が呼び出しの鎖全体で 1 回しか走査されないようにする。
- **パラメータ**: t = max(16, ⌈(lg N/d)^{2/3}⌉)、M_l = t·2^{(l−1)t}、Λ_l = t³·2^{lt}。

意図的な簡略化と、論文との差（いずれも正しさにも漸近的な計算量にも影響しない）:

- **DS'**: ブロックの非空判定を、レベル別の循環キーリストではなく前方ブロックの遅延掃除で行っている。
  分割は論文どおり Pull 時の前方分割だけ。
- **Pmem**: 所有者つきの頂点ごとのスタックはそのまま実装したが、Pl[j] は双方向リストではなく、
  配列と所有者テストで表現した。
- **ディスパッチャ**: 形式プログラムのディスパッチャ（n < 2^16 などで Bellman–Ford に切り替える部分）は再現していない。
  C-HD 本体を常に実行し、形式プログラムならどちらの分岐に入るかは出力の `formal=` 欄に示した。
- **重み**: 整数重み（[1, 2^20]）を f64 で保持しているので、和はすべて厳密で、
  比較・加算モデルをそのまま模擬できている。

`cargo test --release --test bmssp_family_test`（約 1 秒）の内容:

- n < 40 のランダム有向マルチグラフ 3000 個（重み上限 0, 1, 3, 100。ゼロ重み閉路・同値・自己ループ・多重辺・到達不能頂点を含む）

## 5. 分析

**(a) 理論上の改善幅が小さすぎる。**
C-HD と Dijkstra の上界の比は、最大でも lg^{1/12} n 程度しかない（n = 2^22 でも 22^{1/12} ≈ 1.29）。
これに対して実装の定数差は数倍ある。5 つ組ラベルの比較、隣接リストのソート（O(m lg δ)）、ブロック構造、
FindPivots の木構築と分割、Pmem スタックなどがその中身。

**(b) 実用サイズでは再帰がほとんど起きない。**
t ≥ 16 なので L = ⌊lg N/16⌋ + 1 は、n < 2^16 で 1、n < 2^32 で 2 にしかならない。
実行の中身はおおむね次のとおり。

- FindPivots-HD はレベル ≥ 1 の呼び出し（数回しかない）でしか実行されない。t0 = 16 では FH.9 の辺削除は一度も起きなかった。
- レベル 2 は M_2 = 16·2^16 ≈ 10^6 頂点ずつ Pull し、レベル 1 は 16 頂点ずつ Pull して
  Λ_0 = 4096 頂点で打ち切る境界付き Dijkstra（base case）に渡す。
- つまり実態は「二段のバケット付き Dijkstra」で、漸近解析が前提とする深い再帰構造は現れない。
  t0 = 4 にして再帰を深くしても（L = 5〜6）速くはならなかった。

**(c) 比較回数では一貫して負けている。**
`results/opcount.md` のとおり、辺あたりの比較回数は Dijkstra が 3.6〜8.5、C-HD が 12〜19 で、C-HD / Dijkstra は 2.2〜4.0 倍。
d = 16 では比が 3.99 → 3.33 と lg n に対してゆっくり下がるが、d = 4 ではほぼ一定（2.20〜2.28）だった。
単純に線形外挿しても、d = 16 で比が 1 になるのは lg n ≈ 50 あたりになる。
d = 16 は形式的な窓の外（F(2^22) = 10）であり、窓の中の d では減少傾向そのものが見られない。
形式証明の定数を勘案すれば、なおさら実用域での逆転は見込めない。

**(d) コア部分の実時間の追い上げは、メモリ局所性で説明できる。**
比較回数は 2.2〜3.5 倍多いにもかかわらず、n ≥ 2^20 のコア部分は二分ヒープの Dijkstra と同程度（0.98〜1.13 倍）まで近づいた。
ただし、添字付き 4-ary ヒープ（decrease-key でヒープサイズ ≤ n）と比べると 1.12 倍以上の差が残る。
理由は次のとおり。

- Dijkstra は n 要素規模のグローバルなヒープにランダムアクセスし、キャッシュミスが支配的になる。
- C-HD のヒープは base case 内の小さなもの（Λ_0·δ 程度）だけで、残りは連続配列上の選択（BFPRT 相当）で済む。
- 走査は、ソート済み・ポインタ付きの静的 CSR 上で行われる。

これは sequence heap や radix heap 系が二分ヒープに勝つのと同じ種類の効果で、C-HD の定理が主張する改善ではない。
しかも前処理のソートを含めると、依然として遅い。

**(e) DMM+25 はさらに遅い。**
定次数化で頂点数が 2m + n 程度（ランダムグラフで 4〜33 倍）に増え、各レベルで U_i の辺を再緩和する
（relax/m ≈ 14〜21）。辺あたりの比較回数も 93〜112 回ある。そのため 14〜121 倍遅い。

## 6. このリポジトリの既存実装について（再評価）

| 実装 | 実際の中身 | 旧 README の主張 | 今回の結果 |
|---|---|---|---|
| `improved_sssp` (V1) | `dijkstra` と**一字一句同じコード** | 1.1〜1.2 倍速 | `dijkstra` 比 0.84〜1.12 倍（同一コードなので、振れ幅はそのまま計測ノイズ） |
| `improved_sssp_v2` (V2) | 最初の `dijkstra_phase` がフロンティアを空になるまで処理するので、`bellman_ford_phase` は**到達不能** | 1.1〜1.6 倍速、「論文のアイデアに基づく」 | Dijkstra そのもの |
| `core_algorithm` | トップ呼び出しが `sources.len() == 1` なので即座に `base_case`（HashSet を使った完全 Dijkstra）に入り、FindPivots も再帰も**一度も実行されない**。再帰部分も `bound / 2` で分割しており、論文の BMSSP ではない | 「論文に忠実」 | HashSet を使う分、最速の Dijkstra より 1.8〜3.8 倍遅い |

```bash
cargo test --release --test bmssp_family_test                  # 正しさ

cargo run --release --bin compare -- --lg 22 --skip-dmm25       # n = 2^22（約 20 分、メモリ約 6 GB）
cargo run --release --bin compare -- --grid --lg 16,18,20,22    # グリッド
cargo run --release --features count-cmp --example opcount     # 比較回数
cargo run --release --example repo_check                        # 旧ベンチマーク（密グラフ）での既存実装の検算
python3 scripts/summarize.py results/random.csv                 # 表の生成
```

## 8. 結論

- **「ダイクストラより高速」は、形式的に証明された漸近的上界の主張としては成り立ちうる**（Lean の証明自体は今回検証していない）。
  ただし改善幅は lg^{1/12} n、適用範囲は密度の狭い窓、定数は天文学的で、これは著者自身の注記とも一致する。
- **実装して測ると、実用サイズ（n ≤ 4.2·10^6、m ≤ 6.7·10^7）ではすべてのケースで Dijkstra より遅い**
  （前処理込みで 1.47〜7.3 倍）。計算量モデルの尺度である比較回数でも 2.2〜4.0 倍多い。
- コア部分だけを大きなグラフで比べると二分ヒープの Dijkstra に並ぶ場合があるが、
  これはメモリ局所性による副次的な効果で、C-HD の理論的な寄与とは別物である。
  さらに 4-ary ヒープの Dijkstra には並ばない。
